# PG-003A — создать основу Godot-порта

Статус: подготовлено к проверке.

## Изменение

- В `godot/` создан отдельный Godot project, не затрагивающий существующую web-сборку.
- Зафиксированы portrait viewport 480×854, `canvas_items` scaling и Compatibility renderer.
- Точка входа показывает явно временное состояние порта; игровые экраны в этой задаче не имитируются.
- Добавлена структурная проверка конфигурации и сцены средствами Vitest.

## Проверка движком

Godot 4.7.2 выполнен локально в headless режиме: проект импортирован через `--editor --quit`,
`port_bootstrap.gd` прошёл `--check-only`, а smoke test загрузил сцену и проверил статусную
метку (все шаги завершились с кодом 0).
Для повторения на Windows см. `godot/check.ps1 -GodotPath <путь-к-godot.exe>`.

## Следующий этап

Переносить первый завершённый игровой экран отдельно, сверяя его состояния и действия с текущей web-версией. Для runtime smoke check открыть `godot/` в Godot 4.7 stable и запустить main scene. Godot MCP bridge подключён отдельной задачей PG-003C; живую проверку редактора см. в `docs/features/PG003C_GODOT_MCP_BRIDGE_RU.md`.

## Проверка

Полный `npm.cmd run check`, `npm.cmd run version:check` и `godot/check.ps1` должны пройти до слияния. Структурный тест Vitest дополняет, но не заменяет парсер Godot.
