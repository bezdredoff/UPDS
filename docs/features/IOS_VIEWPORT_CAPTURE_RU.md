# Сбор доказательств на iPhone

Это диагностическая сборка на базе #260, без исправления viewport CSS. Сначала собрать исходный переход;
не переключать status bar и не менять safe-area во время этого прогона.

`e2e/tests/viewport-recorder.pw.ts` проверяет включение, неизменность геометрии при включении,
сбор старых/новых rect на синтетическом изменении и работу после offline reload в Chromium.
Этот тест не эмулирует iOS standalone и не является подтверждением исправления трёх симптомов.

## Подготовка

1. Открыть **диагностический candidate preview**, добавив `?qa=1&viewportdebug=1`.
   Обычный main без этой ветки не содержит рекордер. Сверить build ID на overlay и в JSON с candidate.
2. Для Safari просто использовать этот адрес. Для PWA установить именно этот диагностический preview
   через «На экран Домой» после полной загрузки страницы. Opt-in manifest содержит start_url с viewportdebug=1;
   нельзя полагаться на перенос localStorage из Safari в новую PWA. Не удалять stable-установку с игровым save.
   Если уже установлена старая preview-PWA, сначала экспортировать её нужное сохранение и заменить только preview.
3. Записать модель iPhone, точную версию iOS, режим (Safari/PWA), язык, размер текста VN и AUTO on/off.
   Для ожидания на одной реплике выключить AUTO. По возможности использовать одну реплику с портретом во всех прогонах.
4. Если overlay перекрывает арт, `Hide overlay` оставляет маленькую кнопку возврата. Рекордер продолжает работать.

## Три обязательных прогона

Для каждого включить запись экрана **до холодного запуска**, открыть VN с персонажем и ждать минимум30 секунд.
При видимом изменении сразу нажать `Mark rescale`; кнопка ставит временную метку, сохраняет предыдущий/текущий sample.
Не переходить в Diagnostics перед экспортом: прежняя диагностика заменяет VN своим экраном.
Нажать `Copy debug JSON` непосредственно из overlay. Если clipboard недоступен, появится поле для ручного копирования.

* **Safari:** сначала30 секунд без действий; затем скрыть/показать браузерные панели и снова подождать.
* **PWA online:** полностью закрыть через переключатель приложений, открыть с Домой, повторить.
  Отдельно сохранить кадр, где видны весь экран, Dynamic Island и домашний индикатор с нижней полосой.
* **PWA airplane/offline:** заранее дождаться `offlineReady:true` в PWA snapshot, закрыть PWA, включить авиарежим
  и убедиться, что Wi-Fi тоже отключён. Холодный запуск с Домой, та же реплика,30 секунд, экспорт.
  `navigator.onLine` записывается как сообщение браузера, а не как доказательство наличия интернета.

Назвать файлы `safari.json`, `pwa-online.json`, `pwa-offline.json`; приложить записи экрана/скриншоты и приблизительное
время видимого скачка. Если скачка нет, всё равно экспортировать после30 секунд и указать это. Первые15 секунд
сохраняются отдельно, недавняя история ограничена512 snapshots; события —2048. При большом потоке `dropped` сообщает потери.
Рекордер пишет только в память и ничего не отправляет. Экспортировать **до** закрытия/применения обновления: история
не сохраняется через уничтожение процесса или reload. По запросу `Disable next launch` убрать также параметр из URL;
диагностическая Home Screen установка всё равно запускает адрес с флагом — для отключения открыть viewportdebug=0
в браузере или заменить диагностическую установку обычной после окончания исследования.

Отдельно: portrait→landscape→portrait, если iOS позволяет при текущем manifest orientation=portrait. После возврата
подождать30 секунд. Если ориентация заблокирована системой, так и сообщить. Затем провести online-прогон во время
появления update banner. Сохранить JSON **до** нажатия «Обновить», поскольку эта кнопка намеренно перезагружает игру.

## Что сравнивать в JSON

`startup` хранит начало, `recent` — более поздние snapshots. `marked` фиксирует последнюю пользовательскую отметку.
`t` — performance.now, `timeOrigin` связывает его с абсолютным временем. Внутри snapshot:
`state.elements` содержит top/bottom/height, client/scroll, данные изображений и ссылки на computed style;
объект `{styleRef:N}` раскрывается через верхнеуровневый `styles[N]`. `detail.changes` содержит старые/новые rect
и identity узла. Разный суффикс `@N` означает замену DOM; та же identity с другой геометрией — relayout/transform.
`lastBrowserEvent` — ближайшее ранее увиденное событие, **не доказанная причина**.
`captureDurationMs` показывает стоимость измерения. Родной image decode не имеет пассивного события: его завершение
нельзя честно выдать за load; в записи есть load/error, natural size и resource timing.

`bottomHits` — результат DOM hit testing на нескольких нижних координатах. Он не читает пиксели iOS compositor,
а пустой результат за границей layout viewport не доказывает отсутствие нарисованного там изображения.
Именно поэтому необходима запись реального экрана. Один прогон без рекордера полезен для проверки его влияния на timing.

## Контролируемый опыт со status bar — после baseline

`scripts/create-viewport-experiment.mjs` создаёт копию **готового** dist и меняет только статический status-bar meta
в index.html. В исходниках остаётся black-translucent. Пример после `npm run build`:

```powershell
node scripts/create-viewport-experiment.mjs dist C:\git\viewport-black-translucent black-translucent
node scripts/create-viewport-experiment.mjs dist C:\git\viewport-black black
node scripts/create-viewport-experiment.mjs dist C:\git\viewport-default default
```

Каталоги назначения должны быть новыми. Все три копии происходят от одной сборки, с одинаковыми JS/CSS/assets.
Разместить варианты на **отдельных тестовых HTTPS origins**: текущий SW использует stable/preview cache-prefix,
поэтому три соседних scope одного origin нельзя считать изолированными. Свежая Home Screen установка каждого
варианта обязательна; runtime-переключатель meta не является надёжным экспериментом install-time поведения iOS.
Поочерёдно выполнить те же online/offline прогоны. Проверить `statusBar` в JSON и вид системной панели.
Если система игнорирует различие meta, опыт неинформативен; ничего не утверждать по нему.

Не компенсировать новые координаты CSS в том же опыте. Если black/default изменит origin или безопасную область,
текущая dvh+top формула может перестать подходить — это измеряемый результат, не готовое production-исправление.
