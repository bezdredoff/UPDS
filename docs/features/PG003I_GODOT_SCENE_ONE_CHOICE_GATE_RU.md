# PG-003I — scene 1, CHOICE_00 и граница первого Match-3

Статус: на проверке. Основано на merged PR #400 (`885ef92`).

## Перенесённый игровой путь

После `VN0001–VN0022` Story session открывает `VN_SCENE_01_E0_PRE`
(`VN0023–VN0057`). Сцена использует RU/BE/EN каталоги, исходные выражения
персонажей и два фоновых мастера: комнату клуба и раздевалку лёгкой атлетики.
Режиссёрская строка `VN0048` переключает фон; скрытые системные и режиссёрские
строки попадают в read history без показа как обычный диалог.

На `VN0040` reader показывает локализованный `CHOICE_00` с тремя каноническими
вариантами. Выбор записывается в существующее поле Story save `choice` (`A/B/C`),
а позиция переводится на соответствующую стабильную ветку `VN0041A/B/C`.
Общая часть сцены сохраняет исходные IDs и следует после выбранной ветки.
Continue восстанавливает выбранную ветку из того же save; схема и ключ сохранения
не меняются. Уже сохранённые позиции scene 1 используют прежнюю пару `scene/line`.

После `VN0057` reader достигает явной границы уровня `M3_00_LOCKER_TUTORIAL`,
показывает локализованное сообщение и отправляет `match3_requested` через
сигнал композиционного корня. Сам Match-3 runtime и сцена после победы остаются
следующим этапом порта; story save остаётся на границе и не переписывается на
неперенесённую сцену.

## Источники и проверки

`godot/data/locker_scene.json` собирается из canonical screenplay, web narrative
resolver, RU/BE/EN каталогов, character metadata и authored staging. Экспортёр
копирует только используемые исходные изображения. Vitest проверяет snapshot
всех трёх веток, локализацию, первый Match-3 ID и побайтное совпадение арта.
Godot smoke проходит пролог → scene 1 → выбор B → Match-3 gate; дополнительные
cases проверяют A/B/C и восстановление выбора. Полный визуальный review и
проверка портированного Match-3 остаются отдельными.

## Границы

Канонический сюжет, `CHOICE_00`, локализация, save key/schema, веб-runtime и
`APP_VERSION` не меняются. Новые игровые функции и контент не добавляются.
