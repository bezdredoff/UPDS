# PG-003N — единые данные кампании Match-3 для Godot

## Цель

Подготовить полный перенос Match-3 в Godot так, чтобы определения игровых уровней и их игровые ресурсы не приходилось вручную поддерживать в TypeScript и GDScript одновременно.

## Контракт

- `src/data/levels.ts` остаётся каноническим авторским источником уровней на время переноса.
- `scripts/export-godot-match3.cjs` детерминированно формирует `godot/data/campaign_match3_levels.json` по схеме 1 и копирует игровые изображения без изменений.
- Бандл включает все 22 кампанийных уровня: размеры доски, начальный seed, допустимые плитки, веса генерации, отверстия, фиксированные плитки, blocker-слои, ингредиенты, цели и полную начальную раскладку.
- `godot/scripts/match3_campaign_data.gd` загружает бандл и проверяет его общую структуру до использования игровым runtime.
- `godot/data/locker_match3.json` пока остаётся совместимым контрактом экрана M3_00; его можно удалить после перевода экрана и модели на общий загрузчик кампании.

## Границы

Этот срез переносит контент и генерацию начальной доски; он не объявляет порт правил завершённым. Текущая Godot-модель всё ещё ограничена M3_00. Дальнейшие срезы должны обобщить модель для всех целей (сбор плиток, очистка blockers, выпадение ингредиентов), топологии, spawn weights, refill/reshuffle, подсказок и полного поведения пяти specials/их комбинаций. Для каждого слоя сохраняется parity-проверка с TypeScript-источником, пока веб-runtime остаётся действующей версией.

Level Lab остаётся редактором для разработки, а не дополнительным игровым runtime. Его правки должны проходить через канонические определения/формат данных, чтобы в Godot и веб-версии не появлялись независимые наборы production-уровней.

## Проверка

- Vitest сравнивает весь экспорт с live TypeScript-данными и проверяет все 22 уровня и копии игровых изображений.
- `godot/check.ps1` загружает bundle нативным Godot и валидирует количество уровней, крайние ID, карту ресурсов и схему.
- Полные `npm run check` и `godot/check.ps1` обязательны перед merge.
